Third-Party Decimal Libraries

Summary of the decimal libraries used in the lab and how their precision models differ.

Third-Party Decimal Library Summary

  • decimal.js: the broadest option here. It uses significant-digit precision, rounds arithmetic to that precision, and supports more advanced operations such as powers, logarithms, and trigonometry. It is a strong default when correctness and feature coverage matter more than bundle size.
  • bignumber.js: a good fit for financial-style decimal arithmetic. Its configuration is based mainly on decimal places for division-like operations, while add, subtract, and multiply are generally exact until output or operation limits matter. It has fewer advanced math functions than decimal.js but maps well to money/quantity calculations.
  • big.js: the smallest and simplest of the MikeMcl libraries in this comparison. It focuses on core decimal arithmetic with a compact API. Its division precision is controlled by decimal places. It is useful when bundle size and simple arithmetic matter, but it has fewer rounding modes and features.
  • decimal.js-light: a smaller variant of decimal.js. It keeps significant-digit precision but trims features. Its arithmetic behavior differs from full decimal.js because operations are truncated at precision rather than rounded in the same way as full decimal.js, so it can diverge in edge cases despite similar configuration.
  • decNumber WASM: IBM decNumber compiled to WebAssembly. The current lab build is capped at 128 significant digits and defaults to 80 significant digits, but the underlying decNumber library is an arbitrary-precision decimal arithmetic system whose context can scale far beyond this lab build.
  • currency.js: a small fixed-scale currency helper that stores values as integer minor units internally. It is useful for typical currency amounts but is not an arbitrary-precision decimal library.
  • Dinero.js: a money-object library for amount/currency/scale workflows. Dinero.js v1 had divide and percentage helpers; Dinero.js v2 removes both. Division on integers loses information unless a rounding or allocation policy is explicit, so v2 pushes those workflows toward allocation/rates rather than casual division.
  • accounting-js: a number and money formatting/parsing helper. It is useful for display and custom toFixed behavior, but should not be treated as an arithmetic engine.
  • moneysafe: a BigNumber-backed money helper from Eric Elliott. It provides money factories and add/multiply/divide helpers; the lab uses a custom 12dp currency factory for comparison.
  • math.js: a broad mathematics toolkit with BigNumber support. It is not bundled into this lab because it is much larger and much broader than the money/decimal problem being tested here.
  • Practical takeaway: for a finance app, bignumber.js and big.js are often easier to reason about because their division precision is decimal-place oriented. decimal.js and decNumber are significant-digit oriented, which is powerful but can be less intuitive when the requirement is fixed decimal places such as 2, 4, or 12 DP.

The four MikeMcl libraries overlap, but they optimize for different requirements. Pick based on the precision model first, then feature set and bundle/API size.

Short Recommendation For Decimal Arithmetic

big.js is fine if financial front end calculations only needs core decimal arithmetic and these rounding modes:

  • roundDown
  • roundHalfUp
  • roundHalfEven
  • roundUp

In that narrower requirement set, big.js is a good decimal arithmetic replacement candidate: it is small, focused, decimal-place oriented for division, and performs faster than bignumber.js in this lab. Use a thin trading-domain wrapper so business code calls named policies such as price rounding, quantity rounding, money rounding, tax rounding, and reversal rounding rather than raw library methods.

Choose bignumber.js instead when the app needs more rounding modes, broader input/configuration features, non-decimal/base handling, or more escape hatches for future requirements.

decNumber: The Industrial-Strength Decimal Reference

  • Industrial pedigree: decNumber is not just another JavaScript-style decimal package. It is Mike Cowlishaw's IBM-origin ANSI C implementation of General Decimal Arithmetic, with source distributed through ICU and the GCC repository.
  • Hardware-adjacent standardization: IBM POWER6 and System z processors later implemented decimal floating-point support in hardware/software facilities, and IBM documentation uses decNumber as a Decimal Floating Point implementation in z/TPF.
  • decNumber: arbitrary-precision decimal number representation designed for efficient software computation. Once a value is held as a decNumber, arithmetic can continue without repeated string/number conversions.
  • decContext: most decNumber operations take a decContext argument. The context controls precision, rounding mode, exponent limits, status flags, and trap handling for exceptional conditions.
  • Precision range: decContext.digits is an int32 field and supports precision from 1 up to 999,999,999 decimal digits, bounded in practice by build choices, memory, and performance.
  • IEEE decimal floating formats: the package also supports fixed-size decimal floating-point formats: decimal32, decimal64, and decimal128.
  • Fixed-format precision: decimal32 has 7 decimal digits of precision, decimal64 has 16, and decimal128 has 34.
  • decFloat modules: decSingle, decDouble, and decQuad support those fixed formats and are designed to be more compact and efficient than general decNumber for fixed-format work.
  • BCD support: decNumber also includes packed/BCD-oriented utilities, which matters for systems that need decimal storage and conversion formats rather than binary approximations.
  • Formats: values can move through strings, decNumber's arbitrary-precision representation, and the fixed decimal32/decimal64/decimal128 formats.
  • Practical distinction: decNumber is the flexible arbitrary-precision engine; decimal32/64/128 and decSingle/Double/Quad are fixed-size decimal floating formats that trade flexibility for efficiency.
